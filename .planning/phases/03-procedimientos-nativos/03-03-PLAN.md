**Lo que el sanitizador deja pasar** (`apps/web/lib/sanitize-manual-html.ts`,
allowlist **cerrado**):
- Etiquetas: `h2 h3 h4 p br hr strong b em i u s sub sup small ul ol li blockquote
  a img figure figcaption table thead tbody tfoot tr th td caption div span section
  code pre`. **No hay `h1`.**
- Atributos: `a[href,title,target,rel]`, `img[src,alt,title,width,height,loading]`,
  `th[colspan,rowspan,scope]`, `td[colspan,rowspan]`, `*[class]` filtrado contra
  una lista cerrada de clases `manual-*`.
- Esquemas: **`http`, `https`, `mailto`**. `data:` **no** está.
  Comportamiento confirmado de `sanitize-html`: un esquema no permitido elimina el
  **atributo**, no la etiqueta — queda un `<img>` sin `src`, invisible.
- `style` se elimina siempre; `script`, `style`, `textarea`, `option`, `noscript` e
  `iframe` desaparecen **con su contenido** (`nonTextTags`).
- Firma: `sanitizeManualHtml(raw: string): string` — devuelve `""` si la entrada
  está vacía.

**Lo que mammoth hace por defecto** (confirmado en su documentación oficial):
- **Preserva tablas**: filas, celdas, `colspan`/`rowspan`, distinción
  encabezado/dato. Las etiquetas que emite son exactamente las que el allowlist
  permite.
- **Ignora el formato de la tabla** (bordes, colores) y "los detalles de estilo
  como la fuente o el color". Es diseño de mammoth, no un fallo a corregir.
- Mapea "Heading 1" a `<h1>`, que el sanitizador descarta dejando el texto suelto:
  el documento importado se ve plano, sin ningún título destacado.
- Embebe las imágenes como `<img src="data:...;base64,...">`, que el sanitizador
  deja sin `src`.
- API: `mammoth.convertToHtml({ buffer }, options)` → `{ value: string, messages:
  Message[] }`, donde cada `Message` tiene `type` (`"warning" | "error"`) y
  `message`.
- `convertImage: mammoth.images.imgElement(fn)`, donde `fn` devuelve una promesa
  con los atributos del `<img>`. Devolver `{}` produce un `<img>` sin atributos.

**El precedente de ruta a copiar** (`app/api/upload/extract-text/route.ts`): carga
mammoth con `await import("mammoth")`, valida extensión + MIME con una allowlist
cerrada, tope de tamaño, y devuelve JSON. Ya usa `extractRawText` sobre el mismo
tipo de archivo.

**El precedente de autorización a copiar**
(`app/api/upload/document-template/route.ts`): `try` → `requireX()` → trabajo →
`catch` que traduce `UnauthenticatedError` a **401**, los mensajes que empiezan por
`"No autorizado"` a **403**, y el resto a 500.

**Guardias disponibles** (`apps/web/lib/manual-access.ts`):
- `requireManualAdmin()` → ADMIN o SUPER_ADMIN, **y** `documentsEnabled` del
  tenant. Es quien escribe el contenido del manual.
- `requireManualReviewer()` → ADMIN, SUPER_ADMIN o PROFESSOR.
- Los dos lanzan `Error` con mensaje que empieza por `"No autorizado"`, o
  `UnauthenticatedError` (de `@/lib/auth`) si no hay sesión.

**Convención del repo:** los route handlers existen **sólo** cuando hace falta
devolver un `Response`. La importación recibe un `File` dentro de un `FormData`, así
que es ruta y no server action. Nada de despacho ni de correo aquí.

**1. `apps/web/lib/documents/docx-to-html.ts`** — la conversión, sin nada de HTTP,

```typescript
import { sanitizeManualHtml } from "@/lib/sanitize-manual-html";

export interface DocxConversionResult {
  /** HTML ya saneado. Lo que sale de aquí puede guardarse tal cual. */
  html: string;
  /** Imágenes incrustadas que se descartaron. Se le dice al usuario. */
  droppedImages: number;
  /** Avisos de mammoth, en texto plano, para la ayuda del importador. */
  warnings: string[];
}

export async function convertDocxToManualHtml(buffer: Buffer): Promise<DocxConversionResult>
```

Dentro:

a) **`styleMap` explícito**, alineado a mano con el allowlist. Es el arreglo del
   pitfall de los encabezados: sin esto, "Heading 1" llega como `<h1>`, el
   sanitizador lo descarta y el título principal del documento importado queda
   como texto suelto. Incluir las variantes en español, porque el Word de la
   consultora está en español:

```typescript
const STYLE_MAP = [
  "p[style-name='Heading 1'] => h2:fresh",
  "p[style-name='Heading 2'] => h3:fresh",
  "p[style-name='Heading 3'] => h4:fresh",
  "p[style-name='Heading 4'] => h4:fresh",
  "p[style-name='Título 1'] => h2:fresh",
  "p[style-name='Título 2'] => h3:fresh",
  "p[style-name='Título 3'] => h4:fresh",
  "p[style-name='Titulo 1'] => h2:fresh",   // sin tilde: Word lo escribe así en algunas plantillas
  "p[style-name='Titulo 2'] => h3:fresh",
  "p[style-name='Titulo 3'] => h4:fresh",
];
```
   Documentar en un comentario **por qué** empieza en `h2` y no en `h1`: el
   allowlist del sanitizador no incluye `h1`, y el `h1` de la página lo pone la
   plantilla de la plataforma, no el cuerpo del documento.

b) **`convertImage` que no embebe nada**, contando de paso:
```typescript
  let droppedImages = 0;
  const options = {
    styleMap: STYLE_MAP,
    convertImage: mammoth.images.imgElement(() => {
      droppedImages += 1;
      return Promise.resolve({});
    }),
  };
```
   Si los tipos de `mammoth` no exponen `images` sobre el namespace del
   `await import`, probar `mammoth.default.images` antes de recurrir a un `as`: el
   paquete trae sus propios `.d.ts` y el problema, si aparece, es de interoperación
   de módulos, no de tipos ausentes. **No** silenciar con `any`: añadiría una
   advertencia de lint y rompería la línea base de 81.

c) **Quitar los `<img>` vacíos** que deja el paso anterior, antes de sanear:
```typescript
  const withoutImages = result.value.replace(/<img\b[^>]*>/gi, "");
```
   Una expresión regular sobre HTML es frágil en general; aquí es aceptable y está
   acotada: opera sobre la salida de mammoth (no sobre entrada de usuario), sólo
   elimina, y **después** pasa el sanitizador de verdad. En el peor caso deja un
   `<img>` que el allowlist ya sabe tratar. Dejar ese razonamiento escrito para
   que nadie lo "mejore" metiendo un parser.

d) **Sanear siempre, aunque el resultado esté vacío**:
```typescript
  const html = sanitizeManualHtml(withoutImages);
```

e) `warnings`: `result.messages.map((m) => m.message)`, recortado a las primeras
   20 entradas para que un documento con 400 avisos no infle la respuesta.

**2. `apps/web/app/api/upload/document-body/route.ts`** — la ruta, calcada del
molde de `extract-text` para la validación y del de `document-template` para la
autorización:

```typescript
export const dynamic = "force-dynamic";

const MAX_BYTES = 10 * 1024 * 1024;
const DOCX_MIME =
  "application/vnd.openxmlformats-officedocument.wordprocessingml.document";

export async function POST(req: Request) {
  try {
    // Escribir el cuerpo de un procedimiento es autoría de manual, no revisión:
    // la consultora produce el documento, el consultor lo acompaña. Y
    // `requireManualAdmin` comprueba además que el módulo esté habilitado para
    // el tenant, que es la puerta que el resto del módulo ya respeta.
    await requireManualAdmin();

    const form = await req.formData();
    const file = form.get("file");
    if (!(file instanceof File)) {
      return NextResponse.json({ error: "Archivo faltante" }, { status: 400 });
    }
    if (file.size > MAX_BYTES) {
      return NextResponse.json({ error: "El archivo supera 10 MB" }, { status: 413 });
    }
    // Extensión Y MIME, con el mismo criterio permisivo de `extract-text`:
    // algunos navegadores mandan el MIME vacío.
    const nameOk = file.name.toLowerCase().endsWith(".docx");
    const mimeOk = !file.type || file.type === DOCX_MIME;
    if (!nameOk || !mimeOk) {
      return NextResponse.json(
        { error: "Sólo se puede importar un archivo de Word (.docx)." },
        { status: 400 },
      );
    }

    const buffer = Buffer.from(await file.arrayBuffer());
    const result = await convertDocxToManualHtml(buffer);
    if (!result.html.trim()) {
      return NextResponse.json(
        { error: "El documento no tiene contenido que se pueda importar." },
        { status: 422 },
      );
    }
    return NextResponse.json({ ...result, source: file.name });
  } catch (err) {
    // ... traducción de errores idéntica a document-template/route.ts:
    //     UnauthenticatedError → 401, "No autorizado…" → 403, resto → 500
  }
}
```

Registrar con `console.error` el fallo de parseo antes del 500, como hace
`extract-text`: un `.docx` corrupto es información que sólo está en el log.

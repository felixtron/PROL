```typescript
export function resolvePrivateUploadDir(subdir: string): string {
  const base = process.env.PRIVATE_UPLOAD_DIR;
  if (base) return join(base, subdir);
  // ... aviso en producción ...
  return join(process.cwd(), "private-uploads", subdir);
}
```
Con `pnpm --filter @prol/web dev` el `cwd` es `apps/web`, así que sin
`PRIVATE_UPLOAD_DIR` los archivos caen en `apps/web/private-uploads/<subdir>/`.
Sólo hay dos subdirectorios posibles: `evidence` y `templates`
(`PrivateSubdir` en `apps/web/lib/document-files.ts` línea 66).

**La correspondencia que hay que preservar**, y toda la razón de ser de la fase:
```
base de datos        fileKey  = "evidence/<uuid>.pdf"        ← NUNCA cambia
disco                ruta     = <PRIVATE_UPLOAD_DIR>/evidence/<uuid>.pdf
R2                   clave    = prol/evidence/<uuid>.pdf
```

**El interruptor** (`apps/web/lib/document-storage.ts`, tras el plan 02-02):
```typescript
const STORAGE_BACKEND: "r2" | "disk" = isR2Configured() ? "r2" : "disk";
```
`isR2Configured()` exige las cuatro variables. `lib/env.ts` revienta el arranque
si `R2_BUCKET` está y falta alguna de las otras tres; si falta `R2_BUCKET`, no
revienta y el backend es disco. Esa asimetría es la que hace que **`R2_BUCKET`
sea la palanca del rollback**.

**Cómo se fuerza el backend de disco en local sin editar el `.env`:** Next no
sobreescribe variables que ya existen en `process.env`, así que basta con
definirla vacía en la invocación:
```bash
R2_BUCKET= pnpm --filter @prol/web dev
```

**El entorno real de producción** (`DEPLOY.md` líneas 174-181, 237-273, 329, 356):
producción **no** corre `docker-compose.prod.yml`. Usa quadlets de podman, con el

**Herramientas que NO hay:** `rclone` no está instalado ni en el host de

`apps/web/node_modules/aws4fetch` subiendo por el árbol. Node v22 soporta
`--env-file`, y `apps/web/.env` es un enlace simbólico a la raíz.

Cabecera:
```javascript
// Copia el contenido del disco privado (evidencias y plantillas confidenciales)
// a Cloudflare R2, bajo el prefijo `prol/`.
//
// NO BORRA NADA, ni del disco ni del bucket, y NO TOCA LA BASE DE DATOS. Es una
// copia de bytes: las `fileKey` que guarda Prisma —`<subdir>/<uuid>.<ext>`— son
// válidas en los dos backends sin modificarse, y ésa es justamente la propiedad
// que hace reversible el cambio.
//
// El bucket está COMPARTIDO con otro producto en producción (prefijos
// `empresas/` y `leads/`). Por eso aquí no hay ninguna operación destructiva.
//
// Idempotente: si el objeto ya existe con el mismo tamaño, lo salta.
//
//   node --env-file=.env apps/web/scripts/migrate-private-to-r2.mjs [--dry-run]
//
// Variables: las cuatro R2_*, y PRIVATE_UPLOAD_DIR (si no está, usa
// <cwd>/private-uploads, igual que resolvePrivateUploadDir).

import { readdir, readFile, stat } from "node:fs/promises";
import { join } from "node:path";
import { AwsClient } from "aws4fetch";

const R2_KEY_PREFIX = "prol/";
const SUBDIRS = ["evidence", "templates"];
```

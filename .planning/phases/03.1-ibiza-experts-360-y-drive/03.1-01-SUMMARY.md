## Decisions Made
- Caso A de commit (ver arriba): el árbol ya estaba limpio de trabajo ajeno cuando se ejecutó este plan.
- El dev server persistente en `:3000` tenía el Prisma Client anterior cacheado en memoria de proceso (Node no recarga módulos nativos ya importados aunque `db push` regenere el cliente en disco). Se detectó por un `PrismaClientValidationError: Unknown field documentsMenuLabel` al primer `GET /tenant-admin/settings`, y se resolvió matando el proceso (`next dev --port 3000`, PID 44223/44229) y relanzándolo con el mismo comando en background — no un cambio de código, sólo ciclo de vida del proceso de desarrollo.

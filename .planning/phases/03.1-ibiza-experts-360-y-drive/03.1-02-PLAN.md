**1. `components/nav-icons.ts` — la unión.** Sustituir la interfaz plana por:

```typescript
export interface SidebarNavLink {
  href: string;
  label: string;
  icon: SidebarIcon;
}

/**
 * Un grupo desplegable del menú. **No navega**: no tiene página propia, y
 * ninguna de sus rutas hijas cambió de URL al agruparse — el menú es puramente
 * de presentación. Por eso el grupo lleva `id` (clave de React y del estado de
 * apertura) en vez de `href`.
 */
export interface SidebarNavGroup {
  id: string;
  label: string;
  icon: SidebarIcon;
  children: SidebarNavLink[];
}

export type SidebarNavItem = SidebarNavLink | SidebarNavGroup;

export function isNavGroup(item: SidebarNavItem): item is SidebarNavGroup {
  return "children" in item;
}

/**
 * Todos los hrefs navegables, con los grupos aplanados. Es lo que come
 * `resolveActiveHref`, que sigue sin saber que existen los grupos.
 */
export function flattenNavHrefs(items: SidebarNavItem[]): string[] {
  return items.flatMap((item) =>
    isNavGroup(item) ? item.children.map((c) => c.href) : [item.href],
  );
}
```

Los cuatro layouts que hoy declaran `SidebarNavItem[]` planos siguen compilando sin
tocarse: un `SidebarNavLink` es asignable a la unión. `app/admin/layout.tsx` no se
edita.

**2. `components/nav-group.tsx` — el componente compartido.** Cliente
(`"use client"`), y exporta tres cosas para que los tres renderizadores dejen de
duplicar markup:

```typescript
export function groupContainsHref(group: SidebarNavGroup, activeHref: string | null): boolean
export function NavLinkItem(props: { item: SidebarNavLink; active: boolean; nested?: boolean }): JSX.Element
export function NavGroup(props: { group: SidebarNavGroup; activeHref: string | null }): JSX.Element
```

- `NavLinkItem` encapsula el `<Link>` con las clases exactas de arriba y
  `aria-current={active ? "page" : undefined}`. Con `nested`, sólo añade indentación
  a la izquierda (`pl-9` en vez de `px-3`) para que se lea como hijo. Nada más
  cambia: mismo tamaño, mismo hover, mismo estado activo.
- `NavGroup`:
  - Cabecera: `<button type="button" aria-expanded={open}
    aria-controls={"nav-group-" + group.id}>` con el icono del grupo, el rótulo, y
    un `ChevronDown` de `lucide-react` que rota 180° cuando `open` — el patrón
    literal de `knowledge-base.tsx`.
  - Cuerpo: `{open && <div id={"nav-group-" + group.id} className="mt-1 space-y-1">
    …children con NavLinkItem nested…</div>}`. Se **omite del DOM** cuando está
    cerrado, no se esconde con CSS: así el HTML servido dice la verdad sobre lo que
    hay, que es lo que hace verificable este plan por HTTP.
  - Cuando el grupo está cerrado pero la ruta activa cae dentro, la cabecera se
    resalta con las clases de activo. Así nunca hay un estado en el que el usuario
    no sepa dónde está.
  - Estado de apertura, **sin store y sin efecto**:
    ```tsx
    const contains = groupContainsHref(group, activeHref);
    const [override, setOverride] = useState<boolean | null>(null);
    const [lastContains, setLastContains] = useState(contains);
    if (lastContains !== contains) {
      // La ruta entró o salió del grupo: la decisión manual anterior caducó.
      // Ajustar estado durante el render es el idioma de React para "estado
      // derivado que se reinicia con una prop"; con un useEffect habría un
      // frame pintado con el estado viejo.
      setLastContains(contains);
      setOverride(null);
    }
    const open = override ?? contains;
    ```
    Comentar el porqué: es el tipo de código que alguien "simplifica" a un
    `useState(contains)` que deja de reaccionar a la navegación.
